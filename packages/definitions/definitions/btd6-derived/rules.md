# BTD6-derived candidate 0.1

Author a complete `btd6-derived/0.1` unit. This contract implements a bounded three-path tower design. It is not the BTD6 engine. Keep source fidelity, mechanic execution and balance claims separate.

The unit has three named paths of five sequential purchases. Legal builds use at most two paths, and at most one path exceeds tier two. There are 64 distinct builds. No exclusive property ownership is imposed. Upgrades can change the same attack property across paths.

Use `resolution: "upgrades"` for generated units. Resolve purchases in path array order, then ascending tier, irrespective of purchase order. Numeric operations explicitly add, multiply or set. Use endpoint overrides for combinations that need a different result. Overrides replace the entire model. `captured-endpoints` is for imported reference subsets only; absent endpoints fail compilation. The base endpoint must be present. Costs always sum placement plus selected purchases.

Attack reach differs from display range. Global targeting has no distance limit but still observes walls unless throughWalls is true. Contact attacks represent direct reach. Instant attacks have no travel. Projectile attacks are modeled as emissions whose collision and travel require a consuming game. Detection determines eligibility; damage immunity tags prevent damage but consume pierce contacts. Target modes choose highest progress, lowest progress, nearest distance or greatest strength. Ties sort by ID.

An activated ability either fires its declared attacks once or temporarily replaces all local attacks. Direct activated attacks do not change the automatic attack clock and can fire during a transformation. Transformations have a duration in seconds. Only one transformation can run at a time. Activation starts cooldown immediately. Failed activations do not spend cooldown. Expiration restores the purchased base model and preserves ability cooldowns. Entry and reversion each start a full attack cycle, preventing attack resets. No maximum of three forms is imposed. The current candidate supports any declared ability count up to the schema's 32-entry safety bound. It does not support simultaneous transformations, stamina, resource costs, early exit or contextual shared ability cooldown groups.

Attacks can apply `onHit` stun or slow effects. Each effect declares duration, speed multiplier and control immunity tags. Stun requires a zero multiplier. Control immunity is independent of damage immunity: an enemy can take damage while resisting a stun. Each attack ID and effect index identifies a source; another hit from that source refreshes its expiry. Different sources coexist, and the strongest active speed reduction wins. The probe integrates controlled time and normalized movement prevented. It does not move targets through track geometry. These declared refresh and overlap rules require separate parity checks before translating arbitrary captured modifiers.

`replace-attack` and `grant-ability` upsert by ID. Transform attacks are explicit snapshots; base attack upgrades do not implicitly alter them. Each authored purchase must change the resolved combat model in at least one legal immediate before/after tier transition. This rejects empty or fully masked changes while allowing conditional detection and endpoint-specific effects. A model change alone does not establish gameplay usefulness. Explain adaptations and unsupported requested mechanics in the required arrays. Do not disguise missing summons, income, support, bloon layer transitions or Paragon rules as extra personal damage.

The deterministic stationary contact probe uses fixed targets without health or movement. Each emission contacts eligible targets up to pierce in target order. This assumption is useful for testing declared selection, timing, damage arithmetic and ability lifecycle. It does not prove projectile collision, live BTD6 behavior, character fidelity or balance.
