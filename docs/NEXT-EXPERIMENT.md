# Next generation experiment

The problem is not simply that the model cannot emit valid numbers. The retained final batch produced recognizable character proposals, then failed to carry their promises through mechanics and repair. It also misread supplied evidence and reused generic progression. Those are separate failures. The existing gates prevented invalid publication but did not assess the whole design.

This diagnosis uses [the pipeline decisions](PIPELINE-APPROACHES.md), [the test audit](TESTING.md), [the evaluation history](PIPELINE-EVALUATION.md), and local batch `.runs/unit-pipeline/final-benchmark-2026-09-21T21-50-33-334Z`, with the detailed reading in `.scratch/notes/foundation-postreview-free-review.md`. Local artifacts are ignored and may be absent from another checkout. The batch used Nex Mini Free, returned zero drafts from ten successful provider responses, and reported $0. A provider response or retained plan is an intermediate proposal, not a returned valid Unit.

A contract disagreement can therefore originate before numerical generation. It does not by itself refute the prose purchase idea. |

Goku enables Camo detection while denying it in prose. These supported concepts were implemented inconsistently. |
| Repair | Rimuru's final patch removes an earlier cadence improvement while fixing damage and pierce. Goku's patch introduces unrelated zero-radius active follow-ups. Luffy fixes a radius but retains the volley mismatch. Repair can introduce or preserve defects rather than converge. |
| Publication | Rimuru finally fails promised range/cadence checks; Luffy fails a four-effect policy ceiling and purchase promises; Goku fails positive-radius constraints. All three final drafts are rejected. No accepted purchase-evidence report or verified six-crosspath outcome exists for this batch. |

The four-effect ceiling is a policy about representation fields, not proof that a purchase is impossible or overloaded for a player. Changing it would not fix Luffy's missing behavior. Conversely, a zero-radius follow-up violates the current mechanic contract. Ordinary versus active gains and distinct volleys already have vocabulary here; their misuse is not missing Engine support. True gaps, such as an independently operating summon or obstacle-aware delivery absent from the supplied Definition and Engine, should remain explicit proposals. Goku's supposed concave-geometry gap arose from a source misreading.

The same base numbers and early pierce/cadence/range template appear in all three numerical proposals. That suggests weak differentiation, but does not isolate whether examples, prompting or model behavior caused it. Capstone value and crosspath usefulness still require reading the actual purchases under stated enemy and space assumptions. Passing arithmetic cannot establish those judgments or balance.

Keep the current UI. The smallest useful failure view is one retained comparison table, initially Markdown beside the evaluator report: character/purchase, source passage, promised change, typed intent if present, implemented change before and after repair, final gate, and human reason. Link to the existing request and response files. Mark proposals as unpublished. Separate source-reading, policy, unsupported mechanic and implementation findings; allow "unknown" where nothing was reviewed. This can later inform a small details view without introducing an agent framework or composite scorer.
