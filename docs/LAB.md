# Local UnitLab

For qualitative authoring, select **Qualitative concept** beside the character name. The existing numerical mode remains the default. The concept sheet displays complete behavior, activation, path limitations and directional crosspaths without prices or a numerical blueprint. Checks and evidence remain separately expandable.

Inputs and rules accepts imported concept requests, including [the two-path example](../examples/iona.two-path.concept.request.json). Progression and concept policy are editable JSON. Switching the output preset replaces bundled rules and starts a new design; it does not formalize the current concept into numerical mechanics. Saved drafts, checked artifacts and reviewed Results can be reopened and revised. Choose a design revision or a wording-only edit; the latter still needs semantic review before claiming unchanged mechanics.

Concept Draft and Review calls retain evidence under `evidence/` in the configured library directory, including failed attempts. Each run includes original output, exact model inputs, safe configuration and an `observations.json` template. Choose the appropriate library directory before using external project content. Deleting a library entry does not delete its research evidence. See [refinement](REFINEMENT.md) for predicted scenarios, preservation records and acceptance reasons.

`mardwerk-unit` is the minimal local interface to the shared generator core. Run `pnpm install` once, then `pnpm dev` from this repository. Open `http://127.0.0.1:4317` directly. Development mode rebuilds and restarts when source, build scripts, examples or TypeScript configuration change. Refresh the browser after a rebuild; restarting interrupts active generation, and reloading discards unsaved editor state. Stop with Ctrl+C. Use `pnpm dev --port 4318` for another port. For a fixed build, use `pnpm build` followed by `pnpm start`.

Enter a character name and select Generate to open its run immediately. Ctrl-click or Cmd-click Generate to stay on the create page while it runs. You can enter another name, edit its rules and select Generate while other runs continue. Each generation uses a detached snapshot of its own inputs. Plus and the Mardwerk brand open a fresh form without changing the active run. The top activity entries return to individual runs. Background generation lasts while this browser tab remains open; it is not a detached worker. The app resolves matching Wikipedia character evidence, gathers available source images and pose references, adds the bundled default Tower Defense profile, then drafts, checks and reviews a Unit. Ambiguous names need a character selection. A missing reference produces an actionable error; it does not become invented canon. Evidence can be partial, especially for characters documented inside a shared series page.

Source images remain linked to their pages with captions and attribution. Where available, Wikidata identifies a character's Fandom page for further images. Pose and form labels come from filenames and captions, not pixel analysis. These are reference images, not generated assets. The gallery stays empty until retrieval finishes. If no images are found, it shows a short message. Retrieval diagnostics remain in the artifact. URLs and metadata survive session and Result exports; images are loaded from their source rather than bundled for offline use.

Settings contains provider selection and the local library folder. OpenRouter is the default, uses its official SDK and requests `openrouter/free` with zero-price routing. An API key is required even for free models. Enter it there or set `OPENROUTER_API_KEY` in the local `.env` file before launch. Existing environment variables override `.env`; an explicit Settings or command-line model overrides `OPENROUTER_MODEL`. A Settings key remains in server memory and never enters an artifact or session export. An explicit model override may select a paid model. No automatic paid fallback occurs. `pnpm start --provider codex` uses the installed Codex CLI's existing configuration and login.

Role ranking reads server-side environment settings: `UNIT_ROLE_PROVIDER=auto|typesafe|openrouter|off`, `TYPESAFE_API_KEY`, optional `TYPESAFE_MODEL` (default `jev-1.13.0`), and `OPENROUTER_JEV_MODEL`. Auto prefers available TypeSafe credentials, otherwise it uses an explicitly configured OpenRouter Jev model and key. A failure does not trigger another provider. OpenRouter uses its separate Decisions API with `~typesafe/jev-latest` or a supported pinned TypeSafe model ID. One minimal live request verified this route on September 20, 2026. This connection is separate from the draft model. TypeSafe estimates remain separate from reported generation costs; ranking confidence does not measure accuracy.

OpenRouter supports tool calling, but this adapter currently requests strict structured JSON without research tools. The app retrieves source text and image metadata before generation; the model cannot request follow-up pages or inspect image pixels. Select a model and endpoint supporting structured outputs. Thinking Machines Inkling Small currently does not advertise that support and is not a tested option for this adapter.

OpenRouter errors distinguish the app's 120-second deadline from a provider timeout, rate limiting, insufficient credits, rejected requests, unavailable models and invalid output. A received Retry-After value is displayed for rate limits. Error codes and provider status are retained in the API response, with reported usage when available. Raw SDK payloads and source text are not displayed. Retrying is explicit.

OpenRouter reasoning defaults to `none` for interactive drafts. Set `OPENROUTER_REASONING` to `low`, `medium` or `high` before launch to experiment with supported reasoning models. Higher effort can exceed the two-minute call deadline; the CLI supports a longer `--timeout` for such experiments.

The editable BTD6-inspired default profile supplies three paths with five upgrades each, focused early-tier capability budgets, ordinary targeting and delivery rules, and an experimental numerical scale. The [design baseline](../research/btd6/BTD6-UNIT-DESIGN.md) explains the rules and their exceptions; [six tower profiles](../research/btd6/BTD6-UNIT-EXAMPLES.md) document 90 concrete tier changes. These references guide generation and semantic review, not executable balancing. The current preset uses Gold, a 1-health enemy layer and a 1-damage base reference. Its 150 Health means shared player lives; Units have no HP. Name-only Generate starts from this editable preset. To use custom rules or confirmed choices, open Inputs and rules in the workspace. Generate uses edited or imported inputs when the name matches that brief; the page states when this applies. A different name starts a fresh lookup. The visible stage controls can also run explicit inputs one step at a time. Feedback revisions preserve the current explicit inputs and prior Result.

The v5 default rejects identical T1 purchases, requires three declared path specializations, permits a manual boost on at most one path, and checks T5 against an editable specialty threshold. These are authoring heuristics, not balance certification. Existing saved Units retain their original rules. See [the exact policy](MECHANICS.md#default-authoring-policy). Roles describe purpose rather than power; the saved `basic_dps` category displays as Generalist damage.

| Stage | Outcome | Model calls |
| --- | --- | --- |
| Prepare | Resolved sources, rules and input hash. | None |
| Draft | One connected Unit candidate, then optional advisory role ranking. | Draft call, bounded design repair and optional ranking |
| Check | Deterministic structural findings. | None |
| Review | Separate semantic review against the evidence. | One |

The sidebar controls execution. Each available step has a play button to run only that step; completed steps have a rerun button. A rerun creates a new revision and retains the previous artifact. Later stages wait for their prerequisites. Continue runs the remaining stages from the last completed artifact. Stop cancels the active operation and retains completed stages. Find references only performs retrieval and preparation without a model call. Edited inputs must be prepared before a later step can run. Costs from reused upstream artifacts still belong to those original calls, so revision totals must not be summed as an account bill. Stage completion does not certify runtime behavior or balance. The main result shows the kit with a short draft status. The full check report, including failures, is collapsed below the kit. These findings describe problems in the generated output or missing specifications; users do not need to edit technical identifiers. View checks opens the report. Try improving draft sends the current inputs and findings through one new authoring revision, retaining the prior version and confirmed decisions. It uses the configured generator model and can still leave unresolved issues. For an unfinished review, Finish review completes the remaining stages first. Feedback also supports explicit design changes and comparison with earlier work.

Generate contains only the new character input and optional rules editor. Library groups locally saved work by source anime or series and shows Unit portraits. Unit contains the run and character sheet, with revisions and exports below it. Stage completion never changes the current view. The React interface uses Lucide icons and T3 Code's dark neutral surfaces and blue accent. A gallery on the left, a character sheet in the center, and the generation flow and usage on the right separate references, design and execution details. On smaller screens these sections stack. Settings includes an optional role-ranking selector: auto, TypeSafe, OpenRouter or off. After drafting, a compact Roles panel shows advisory rankings for the resolved base and pure tier-five builds. These labels do not alter mechanics. Missing credentials or provider failures retain the draft with skipped or unavailable ranking status; Stop still cancels the operation. Each revision shows reported cost and tokens for Draft, Review and optional role ranking. Only total cost and tokens appear below the flow. Per-stage counts and routed models remain in saved artifacts. Unreported values remain unavailable; partial totals are labeled. Reasoning and cached tokens are already included in token totals. Failed attempts show any returned usage with the error, separately from successful totals. Cancelled or timed-out calls may have no usage report, so this is not a complete account billing ledger. The Codex adapter currently does not report usage.

The local library retains saved generation artifacts across page reloads and server restarts. Completed Results are saved automatically; Save to library retains an earlier completed stage. Open a library entry to inspect or export it while another Unit generates. You can start another generation while existing runs continue. Each run has its own revision, stage, choices, errors and Stop control; stopping one does not cancel the others. Top-bar activity entries return to individual runs, and the revision selector remains available during generation. Ctrl-click or Cmd-click Generate starts an independent run without changing the selected revision. Background completion updates only its own revision and saves its completed Result. Browsing never replaces another run’s inputs or sheet. Edit this Unit opens saved inputs for continued authoring even while other runs are active. Gameplay comparisons show readable previous and current values, including added and removed content, without internal evidence identifiers. JSON and Markdown exports remain compatible with the CLI. Download a session to preserve additional unfinished editor content and tab revisions. Closing or reloading the tab cancels all running generations and loses editor changes that have not been saved.

The default library folder is `.runs/library`. Change it in Settings to use another local folder. Relative paths resolve from the server's working directory. The choice is saved in `.runs/lab-settings.json`; both defaults are ignored by Git. Changing folders leaves existing entries in their original location, and choosing that folder again restores its listing. Provider keys remain in server memory and never enter library settings or saved artifacts.

The Unit overview places General information, including the declared placement cost, beside Basic attack and its combat statistics. These cards stack on narrow screens. Undeclared footprint values are omitted. Upgrade cards show purchase cost and stat changes with icons. Hover for stat or currency labels. Values compare the previous tier with the new tier on that path alone, without a crosspath. Click anywhere on a card, or focus it and press Enter, to open the full explanation. Its image button opens icon generation separately. Older drafts without a structured mechanics blueprint retain their authored text; the Lab does not infer numbers from prose.

Each entry is a managed `unitlab-<content hash>.json` document containing the complete artifact, a format marker and a saved timestamp. Saving identical content again reuses the existing entry. Imports and saved entries receive the same schema and prepared-input hash validation as the Lab's inspection operation. Unrelated, invalid or symlinked documents are omitted from the library and are never eligible for its deletion operations. Delete removes only selected managed entry files; cleanup previews older entries before deleting the selected IDs, preserving the most recently saved artifact at each stage for every character and source scope. Neither action deletes the library folder or unrelated files. Deleted entries cannot be restored by the Lab, so export any work you want to keep first.

The authenticated HTTP interface exposes `GET /api/library` for `{ directory, entries }`. Its JSON POST operations are `library/save` with `{ artifact }`, returning entry metadata; `library/load` with `{ id }`, returning `{ artifact }`; `library/delete` with `{ ids }`, returning the updated listing; and `library/configure` with `{ directory }`, returning the selected folder's listing. Metadata includes `id`, `savedAt`, `kind`, `character` and `artifactId`. These operations belong to the local Lab adapter; the shared generator core remains stateless.

The Unit header pairs its name with the selected or highest-ranked available portrait reference. If reference images are absent or fail to load, a portrait placeholder offers a character-image prompt with no lettering. Original characters use the supplied identity, scope and design direction. Generated portraits use a separate destination from older wordmark assets, which remain untouched.

Icon placeholders use automatic PNG destinations beneath the selected library's `assets` folder. Copy image prompt copies only the visual brief for any image generator. Copy Codex prompt adds the absolute destination and automatic filename. Save the generated PNG there, then refresh the icon previews to display it. The Lab can also generate one image after confirmation, save it at the chosen destination and reload its preview. Source images are not uploaded in this text-to-image flow. Icons are shared across revisions with the same retained character name, source work, scope and attack or upgrade identifier. Library entry deletion and cleanup retain these images.

`POST /api/library/icons` accepts `{ artifact }`, validates it and provisions deterministic icon folders. It returns `{ directory, icons }`, where each icon has a `key`, absolute `path`, optional PNG `dataUrl`, and optional `note` for a file that cannot be displayed. Keys are `unit-portrait`, `basic-attack`, `tier:<path id>:<tier number>`, and `ability:<ability id>` for abilities not referenced by an upgrade tier. Prepared inputs have no icons. Missing images leave the placeholder available. The endpoint reads only the derived filenames, rejects symbolic links and nonregular files, identifies PNG signatures, and limits each image to 8 MB and combined encoded previews to 16 MB. The browser performs image decoding. It accepts no caller-supplied read paths or filenames.

The server binds to `127.0.0.1`, checks its host and origin, and requires a fresh session token on every start. The local page receives that token automatically in uncached HTML; users need no token link or stored browser session. This token is separate from the server-only provider key. The server retains the explicit local library and rejects browser requests to read arbitrary local file paths. Adaptive Jev intake, mechanics retrieval, optimization and gameplay simulation remain proposals in the [authoring workflow](AUTHORING-WORKFLOW.md).

## Generating an icon

Click an icon placeholder, then Generate with the configured model. The confirmation names the model, estimated price and existing PNG destination. Only Confirm and generate submits a paid request. A configured OpenRouter key is required, even when Unit drafting uses Codex. The default is `meta/muse-image`, listed at approximately $0.01 per image. [Image generation](IMAGE-GENERATION.md) documents the connection and pricing.

A successful request saves the PNG in the Unit's existing assets folder and refreshes the preview. Every image call retains its own model, timestamp and reported usage receipt beside the PNG. Reported image cost appears in the icon dialog; it is separate from Unit drafting cost. No image is generated automatically, no retry occurs, and unavailable endpoints do not trigger a different model. Closing the dialog cancels waiting, though provider charges may already have occurred.

Image model selection is in Settings or `OPENROUTER_IMAGE_MODEL`. Changing the model or destination invalidates an old confirmation; the library folder cannot change during a generation. The server accepts only a Unit-owned icon key and compares the displayed destination with its own generated path. PNGs are limited to 8 MB each and previews to 16 MB combined. Manual image and Codex prompt copying remain available without a provider key.

On wide displays, upgrade path headers and matching tier rows align. Open details shows an upgrade and its linked abilities in a dialog without changing the row height. Escape or Close returns focus to the button. Narrow displays stack paths. The Generate input remains centered and narrower than the Unit sheet.

Portraits are chosen independently of the reference gallery. The default ranking uses source captions and filenames, not face detection. Select a gallery image and choose Use as portrait to save a local preference shared by the sheet and library. Retrieval reserves a slot for a full-body reference when one is identified in source metadata; missing coverage is recorded as a research gap. A portrait choice does not remove full-body or action references.
