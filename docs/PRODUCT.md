# Unit Generator

Unit Generator is a standalone Tool for adapting requested characters into Tower Defense units. Authoring can begin with explicit game scope and a partial Game Definition, then propose missing mechanics. Generation and validation against those mechanics require sufficiently specified rules and applicable Profile values. Its Engine owns unit generation, source evidence, mechanic interpretation and scoped validation. Unsupported abilities must be reported; extending a game's mechanics requires an explicit Definition change.

The Tool provides an adjustable default Profile and returns inspectable content, evidence and findings. Its CLI has no hidden state between calls. The optional UnitLab uses the same Engine and retains local settings, work and generation history; earlier Results become explicit inputs when reused.

The local app is named `mardwerk-unit`. Its default flow starts with a character name, retrieves available text and visual references, supplies an editable starter Profile and returns a Unit draft. Source images and pose references accompany the kit with attribution and retrieval gaps. The React Lab presents a character sheet with a left reference gallery and right workflow and usage panel. Inputs and rules belong to the workspace. Settings holds provider configuration and the local library folder; saved generations can be reopened or removed. OpenRouter free routing is the default connection; local Codex remains an option.

Units must satisfy their declared requirements. Scoped checks alone do not establish balance across a game or player appeal. Towerright or another caller supplies wider evaluation and feedback; Towerright also retains project context and can provide curated Profiles.

Engine, CLI and UnitLab remain in this repository. The Greenfield implementation supports structured authoring, scoped checks and a [minimal local UnitLab](LAB.md) for trying the stages and comparing revisions. The default structured mechanics definition now resolves purchased builds, crosspaths and attack boosts. Combat simulation and runtime execution remain outside the current implementation.

## Requested next direction

Explicit concept mode now uses the existing core, CLI and UnitLab for qualitative generation, scoped checks, save/load, revision and rendering. The versioned public concept policy allows bounded early auxiliary behavior and uses configurable progression, activation slots and directional crosspath coverage. Original public examples exercise two different concept rulesets. This preserves rich proposals without asserting numerical or runtime support. Numerical `planned-v1` remains the default; a later comparison determines whether to promote concept authoring.

The normal user input should remain a character name, with the game configuration selected once. The intended output is a complete unit under that configuration. The current checked draft is an intermediate milestone; playable output requires a compatible Consumer and runtime evidence. The generator should choose a coherent source organization before filling purchase slots. The core must permit different progression and mechanic implementations, with the public BTD6-based default separate from private shared forms and stamina.

[GENERATOR-RESHAPE.md](GENERATOR-RESHAPE.md) records the code audit, proposed boundaries, completion states and staged acceptance. [REFINEMENT.md](REFINEMENT.md) describes controlled improvement. ## Authoring contract

The [generation foundation](GENERATION-FOUNDATION.md) defines construction and evaluation responsibilities. A compact purchase plan records player situations, promised changes and retained weaknesses. Deterministic comparisons support review; they do not establish tactical value or balance.

Authoring accepts character identity and source scope, supplied evidence or research permissions, game rules and Profile values, confirmed choices, the requested outcome and relevant earlier Results. Partial rules permit exploration; missing behavior remains visible and cannot receive a successful mechanics check.

The default first plans a sourced character repertoire and three purchasing reasons, then compiles their progression into numerical mechanics. The retained plan states branch destinations, weaknesses, capstone value and crosspath contributions. Revisions use the same process. Generic attack compatibility alone must not choose the entire Unit.

The Result connects role, attacks, progression and abilities with source evidence, mechanic requirements, proposed Definition extensions and actionable findings. Confirmed choices remain distinct from adaptations and unresolved questions. The [standalone example](AUTHORING-EXAMPLE.md) shows this with wall perception: legal upgrade combinations do not authorize through-wall delivery.

The [CLI](CLI.md) exposes combined authoring and individual preparation, drafting, checking and review stages. The [API](API.md) serves applications directly. The [workflow](AUTHORING-WORKFLOW.md) separates implemented authoring from proposed adaptive intake. No particular provider is required by the product contract. The [mechanics DSL](MECHANICS.md) supports bounded attack and upgrade resolution; runtime execution, gameplay simulation and game-wide balance remain outside this scope.

The BTD6-inspired default uses three five-tier paths. T1 and T2 improve the existing basic attack without changing its general identity. T3 commits to a narrower specialization, usually changing the attack behavior. T4 strengthens that specialization and T5 is its ultimate version. At most two paths may be purchased: once one reaches T3, the secondary path stays available through T2, and the third path stays closed. For example, `3-0-0 → 3-1-0 → 3-2-0` is legal; `3-3-0` and `3-2-1` are not. These defaults are explicit Profile rules, not restrictions on every future game.

## Requirements from character design

These requirements came from the September 19, 2026 Luffy, Alucard, Tatsuya, Gojo, Rimuru and Goku design passes. They preserve adaptation decisions and proposed validation cases. Consult [CLI](CLI.md) and [MECHANICS](MECHANICS.md) for implemented guarantees.

Research inputs must identify the character, source work, selected period or continuity, evidence access and further research limits. Retain preferred references and fidelity direction. Links are research entry points, not proof of every claim or an exhaustive boundary. Research referenced abilities before asking the user to establish canon; return consequential adaptation choices after identifying behavior, limits and period. Inaccessible sources remain gaps. User-supplied extracts retain attribution and the access limitation rather than becoming independently verified evidence.

A source fact does not automatically authorize a game effect. Check prerequisites: counterattacks to incoming damage need an incoming-damage system, and defensive powers do not imply Unit HP. Official material about another game's adaptation can establish a technique's identity without importing its damage, controls or resources. Missing behavior should produce a finding with the affected part, governing rule, evidence and required correction or decision.

Progression inputs must declare branches, depth, shared unlocks, prerequisites and legal combinations. Connect the repertoire to a recommended arrangement and useful alternatives. Distinguish innate, purchased, reserved and omitted powers; not every source ability needs a slot. Moving an ability must reveal changed roles, dependencies and lost combinations across legal builds. A form's visuals cannot grant unpurchased effects. Path count, currency, shields, cooldown sharing and fusion rules come from the supplied Definition, not universal Manga Mayhem defaults.

Confirmed decisions bind revisions; unconfirmed arrangements may change. Intentional mixtures of source periods are allowed when requested, while their source distinctions and consequences remain visible. Alucard's before-and-after paths and Red Sea utility branch are such an adaptation. A later state that relinquishes an earlier army must not silently retain it without that direction. Validate crosspaths and any fusion under the supplied rules.

Checks must distinguish supported behavior, allowed but unspecified behavior, conflicting behavior and unsupported capabilities. A caller's Definition extension does not implement an Engine operator. Canon-themed labels, legal combinations and model reviews do not establish executable mechanics, balance or Acceptance. Results also expose spatial requirements for a caller or Map Generator.

The following cases retain the concrete behavior distinctions needed for future validation:

- A stretching punch needs delivery, collision, hit count and obstruction rules. Range alone cannot establish them. Attached limbs and terrain changes can require new Definitions rather than numerical Profile changes.
- Partial armor bypass must name the protection bypassed and retained. In the supplied example, a shield intercepts the entire combined hit; without a shield, the bypass portion reaches health while armor remains. These are example-specific rules.
- A persistent form selector separates configured variant, activation command and active effect. Preserve selection scope and persistence, activation readiness and active-form restrictions. Configuration alone is not transformation; the consumer chooses the UI.
- Alucard's confirmed regeneration is continuous across every legal path and during Stun. Preserve duration reduction separately from triggered removal and specify what happens to effects already present when the upgrade unlocks.
- Red Sea separates map-wide attack scope, summoned actors and their operating areas. A global attack grants neither global summon movement nor unlimited summons. An ordinary capstone active remains distinct from fusion.
- An anchored manifestation needs perception source, valid attack-origin selection, delivery and attribution of upgrades and disabling effects. Multiple appearances cannot silently create independent attackers. Alternate origins, autonomous summons and relocation have different actor and spatial contracts.
- Tatsuya's perception and attack-obstruction exceptions need independent scope and unlock conditions. Wall perception grants neither wall delivery, camo detection nor unlimited range. A confirmed persistent wall-access upgrade must not acquire an invented activation window or uptime cooldown; ordinary attack disabling conditions still apply.
- Restoration under a disabling effect needs explicit permission to start and finish. That exception cannot leak into ordinary attacks or unrelated abilities. Preserve cleanse exclusions. A multi-target capstone expands the earlier single-target behavior only at its declared tier, retaining chant, activation, cooldown and removal rules unless changed. Missing count, selection or reach does not mean unlimited support.
- A legal crosspath with wall access and an area attack proves both capabilities are owned, not that the area attack inherits the exception. Preserve tier assignments and per-technique scope. Personal precision or range likewise does not authorize allied detection. Qualitative promises such as reliable attacks need operational meaning before checking guaranteed hits, bypass or immunity.
- Anti-magic distinguishes interrupting a pending spell, suppressing future casts and removing an applied effect. It needs an enemy-action model and eligible events. Cleanse or Stun does not automatically implement countering; formula memorization does not authorize arbitrary runtime copying.
- Rimuru separates acquisition, storage, analysis, configuration and use. Declare the technique catalogue, acquisition conditions, progression gates and behavior without a compatible sample. Expose unsupported samples and repeated rewards from regenerated enemies. Automatic ordinary-attack selection must retain manual activation requirements. Evolving skill names and Ultimate Skill rank do not establish unlock or fusion rules.
- Goku's teleporting Kamehameha is a prepare, move, fire and return sequence. Distinguish movement from an alternate origin and specify disabling effects, failed destinations, completion and return space. Another character's teleport or form rules are not implicit defaults.
- Gojo's Infinity and Goku's Ultra Instinct distinguish prevention before an impairment from restoration afterward. Declare eligible effects and availability. A defensive source ability does not imply universal immunity in a game without actor HP.
- Composite techniques can require basic capabilities without every related specialization. Environmental prerequisites must be retained, deliberately adapted or left unresolved. Show affected builds and map scenarios. An upgrade depending on a later form must distinguish its immediate and conditional benefits.

The original design pass established no complete validated kit. Future evidence should show both a fully supplied candidate satisfying its declared rules and an unsupported candidate returning an actionable finding. The Engine states its check scope; the caller retains game-wide balance, usefulness across maps, appeal and Acceptance.
