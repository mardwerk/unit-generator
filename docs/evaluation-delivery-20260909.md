# Production qualification and captured reference checks

The delivered evaluator returns findings and readiness rather than a combined quality score. Structure, purchase usefulness, description agreement, source fidelity and balance remain separate. A model that passes mechanical checks still requires source review. The base mechanics belong to the shared engine used by the default contract and MangaMayhem; MangaMayhem adds its form, resource and Technique rules.

`packages/unit-lab/src/qualification.ts` provides the same `qualifyUnit` entry point used by CLI generation and the web editor. Complete authored units get all 64 legal three-path builds and every legal purchase edge. Partial captured families get the available executable builds and edges, with missing endpoints reported separately. A purchase that changes only cost, display metadata or identity labels has no executable benefit. Replacements that mask an earlier path are reported at the affected purchase with before/after tiers. A range display change is reported separately when another useful attack effect is also present.

The production `tower-defense` definition requires the shared `.2` contract even when a candidate omits its schema version. The legacy `btd6-derived` definition remains supported. Range warnings track existing attacks by ID, so a newly added useful attack cannot hide unchanged reach on the original attacks.

MangaMayhem purchases that increase pulse or emission `cycles` get a factual warning. The field raises the number of successful primary attack cycles required for one trigger; it does not add waves. A cycle counts once when a primary hit applies positive damage, regardless of collateral targets. The warning allows useful tradeoffs such as greater damage or radius. Pulse observations count stun triggers and affected targets, not damage. Projectile sweeps and multi-hit sweeps fail contract validation before any encounter runs. These checks do not certify that prose claims describe the mechanics accurately.

Conditional status probes compare explicit required target tags with targets that have no supplied tags. Eligibility uses the adapter-normalized target facts; arbitrary tags remain caller supplied. The evaluator records applied status IDs for both cases. Purchases that add global flat damage also warn when an already unlocked attack or Technique has zero base damage, because the bonus applies to that profile too. These observations keep omitted caller facts and prose restrictions visible without inventing character-specific rules.

The automatic encounters place targets inside the smallest positive executable reach across the candidate's builds. They exercise ordinary, dense, concealed, armored or immune targets as applicable. Range purchases also get a target between old and new reach. Ability probes cover initial activation, an immediate repeated request and bounded transformation expiry. MangaMayhem probes enter each unlocked form, request its available Technique, return to base, exercise target death during windup and check healing on an injured living ally. Declared direct-contact retargeting must hit the remaining eligible target at the original hit time after its first target dies during windup. Other encounter runs are coverage observations. They do not assert that every conditional behavior is correct, and the report names the sequences still unassessed.

Intended-job cases are stronger. `checkBtd6Capabilities` accepts independently justified bounds for damage, distinct contacted targets, controlled targets and prevented movement. It reports the expected job, measured result and discrepancy. Missing, unknown, nonfinite or contradictory bounds are rejected. No damage threshold is invented for a generated character.

## Captured development run

The private `btd6-all-reference-v2-inventory` export accounts for 2,167 captured endpoints, 790 upgrade records and a progression record. All exported file hashes were rechecked. The first executable pass covered 267 model/0.1 field views with 1,476 probes; the other records retained their source facts and explicit missing execution. That is partial executable coverage of the full capture, not a claim that every BTD6 mechanic runs.

Before viewing results, an independent agent reviewer derived two-second expectations for Ninja 000, 100 and 200 and Sniper 000 from captured cadence, damage, pierce, reach and detection fields. The local probe uses a half-open interval and fires at time zero. These scheduling assumptions are local contract rules, not observed live-game timing or human playtest judgments.

Across four endpoints, 24 intact and deliberately modified cases produced 96 observations. Every result agreed with the frozen analytic judgment. Cases included single targets, four colocated targets, concealment and a target outside Ninja's radius. Zero damage, tenfold attack interval, reversed detection and lost radius failed their intended jobs. Renaming preserved the observations. Changing the unused radius of a global Sniper attack also preserved them. The independent reviewer checked the results against the frozen expectations after execution.

This calibration changed the evaluator. Fifteen captured Sniper models contained numeric pierce greater than one on instant attacks. The first detector incorrectly treated that field alone as a blocking crowd promise. It now reports unused pierce as a capability warning. A separately declared forty-target stun still fails when an instant attack controls only one target. The private before/after reports preserve the correction. The captured source is not marked invalid merely because it retains an unused numeric field.

The shared engine also passed 11 independently predicted intact and modified reference cases using captured Banana Farm 000 and Monkey Village 000. Farm checks covered production value, manual collection and pickup expiry. Village checks covered eligible recipients, range boundaries and unique support stacking. Zero production value, unintended automatic collection, premature expiry, missing range benefit and unintended global support failed their supplied jobs. Renaming preserved behavior. Setting the support radius to zero preserved its effect on a colocated recipient but lost the effect on a recipient at distance 20. This provides a useful check against an evaluator that treats every changed number as a changed outcome.

The later `btd6-full-families-v2-strict` export contains all 26 regular families in the same Unit format used by the generator, with all 64 legal endpoint slots and all 15 upgrade descriptions per family. The evaluator executed 126 of those 1,664 slots and checked 194 purchase edges between available models. The combined endpoint and family run completed 1,358 probes; those two passes overlap and must not be counted as distinct captured endpoints. The other 1,538 family slots remain explicitly unresolved. All 26 family reports are therefore blocked for complete executable qualification. Exporting every captured unit is complete in this artifact; executing every captured mechanic is not.

The strict export removed the earlier permissive field-view fallback. Its lower executable count is a correction to coverage, not a reason to restore the fallback. Identical translated purchase models identify missing executable differences in the translation. They do not prove that the original BTD6 upgrade lacks a useful job. Farm and Village's 11 expected-job judgments passed again against the strict export.

Eight more intact and modified cases checked Engineer 100 and 200 sentry creation and expiry. All eight matched the independent expectations. The captured producer intervals are 10 and 5 seconds and the captured child lifespan is 25 seconds. First creation at time zero is an explicit local scheduling policy. Cases crossed the first expiry boundary, preserved behavior under a consistent actor/reference rename, and detected premature expiry and incorrect production intervals. The shared-engine comparison now contains 19 judgments. Parent removal and redeployment remain outside these fresh-encounter cases.

The latest sealed `btd6-full-families-v2-components-enum` export adds complete translations and partial component mappings. Its manifest hash is `6f20606d9e7dbc1e592275c7bc0f26e46509cb1cf05cfee4aee24504170a27bf`. The evaluator verified all 3,013 manifest records, executed 130 family builds and checked 197 available purchase edges. The endpoint and family passes completed 1,514 overlapping probes. All 26 families remain blocked for incomplete executable coverage, with 1,534 of their 1,664 slots unresolved. The 19 independent shared-engine jobs still agree with their supplied expectations. Partial status, modifier and targeting mappings, preserved hero progression records and source taxonomy counts do not increase whole-endpoint acceptance.

These cases use actual exported fields and the shared runtime's declared scheduling. They do not establish that a static capture contains every game trigger or that the runtime matches live BTD6. Source type classification, preserved fields and simulated behavior have separate coverage. Unreviewed source types cannot become executed coverage through a category count.

The September 12 continuation produced `btd6-full-families-v2-resume-20260912` from the existing capture, with no game launch. Its report hash is `ff7e4a3490bf212ee0a514f9f5379a7ff6abf08ee5c151494b7dec7f74cb26cf`; verification rechecked 3,250 files. The family evaluator exercised 160 of 1,664 endpoint slots and 246 purchase edges. Endpoint and family passes completed 1,840 overlapping probes. The remaining 1,504 slots are unresolved, so all 26 families remain blocked for complete qualification. All 19 supplied Farm, Village and Engineer job judgments still agree.

That continuation caught an evaluator input defect. Ordinary targets omitted their tag list, which left tag-dependent projectile modifiers without required facts. Ordinary and range-boundary probes now explicitly supply an empty tag list and visible-target state. This restores those probes without weakening the runtime's missing-fact errors for callers. A regression exercises tag-dependent projectile modifiers across every legal build and range boundary. The first report is retained separately from the corrected report.

All inspected families are development evidence. No untouched holdout remains in this run. Raw source captures and full reports stay outside public artifacts. The old frozen Luffy comparison and its ledger were not changed.

## Reproduction

After building packages, run `node scripts/qualify-reference-export.mjs PRIVATE_EXPORT_DIRECTORY PRIVATE_REPORT_PATH`. The script guards the calibration premises before execution, including delivery, projectile count, attack count, controls, reach, cadence, damage, pierce and detection. Changed premises require a new review of the expected result.

The development reports are `.scratch/delivery-evaluation/corpus-qualification.json` and `.scratch/delivery-evaluation/corpus-before-unused-pierce-correction.json`. They are local evidence, not checkout or CI dependencies. Package regressions use authored fixtures and assert invalid-candidate rejection, masked crosspaths, display-only purchases, low-reach contacts, label invariance, intended-job failures and the crowd-stun distinction.

Run `node scripts/qualify-shared-reference-jobs.mjs PRIVATE_EXPORT_DIRECTORY PRIVATE_REPORT_PATH` for the Farm, Village and Engineer jobs. The local result is `.scratch/delivery-evaluation/shared-jobs.json`. The script verifies exported unit-file hashes and checks the source-field premises before comparing outcomes.

The strict results are `.scratch/delivery-evaluation/full-families-strict.json` and `.scratch/delivery-evaluation/shared-jobs-strict.json`. The full family run uses `--without-legacy-calibration`; its shared-engine jobs are recorded separately from the earlier contact-probe cases.

The latest sealed-export results are `.scratch/delivery-evaluation/full-families-components-enum.json` and `.scratch/delivery-evaluation/shared-jobs-components-enum.json`, using the same commands. Earlier reports remain artifact-specific development evidence.

The September 12 results are `.scratch/delivery-evaluation/full-families-resume-20260912-fixed.json`, `.scratch/delivery-evaluation/shared-jobs-resume-20260912.json` and `.scratch/delivery-evaluation/resume-export-verification.json`. The report without the `-fixed` suffix preserves the ordinary-target input failure. The schemas, shared projectile timer checks and source-enabled mechanics tests can all run without the game.

Source support still needs claim-by-claim evidence. A captured page, a URL or a generator's self-assessment cannot certify canon accuracy. Balance needs representative encounters and a declared game economy; stationary damage observations cannot supply it.
