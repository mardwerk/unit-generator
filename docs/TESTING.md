# What the checks establish

The test suite protects software behavior. It does not establish that generated Units are interesting, faithful or balanced. The September 21, 2026 foundation batch `final-benchmark-2026-09-21T21-50-33-334Z` returned no usable drafts despite all software tests passing. [Pipeline evaluation](PIPELINE-EVALUATION.md) owns subsequent run evidence. Reporting that pass count as evidence of product quality was misleading; generation outcomes belong alongside it.

This September 22, 2026 audit distinguishes three things: tests executed during development, validators that reject a generated candidate, and judgments about its quality. Deleting a test does not change a runtime validator. Passing a fixture says only that the specific operation behaved as asserted.

## Keep contracts, remove unproven design requirements

Keep arithmetic, legal crosspaths, integer hit counts, scoped inheritance, usable active prerequisites, source joins, preserved revisions, cancellation, concurrent jobs, usage accounting, credentials and filesystem boundaries. These requirements matter before the first accepted Unit. A small artificial attack is sufficient to test arithmetic; it is not a reference-quality character design.

Keep custom-policy tests when the caller explicitly opts into that policy. For example, a custom threefold capstone requirement must work if requested. That does not make threefold growth a valid universal BTD6 rule.

This audit removed four recipe snapshot tests and loosens unrelated inventory assertions:

- No requirement that every reference T3 change attack behavior or every T5 improve a chosen metric threefold.
- No fixed T4 follow-up ban or minimum three-hit T5 follow-up in catalogue tests. Scoped inheritance remains checked at the actual purchased tier.
- No assertions that one proposed Black Flame kit must have exactly the current radii, burn values or follow-up counts, or that the catalogue must contain one particular selection of jobs and deliveries.
- No requirement for exactly five reference recipes, version "2", three worked examples, three different role labels or an arbitrary minimum explanation length. Catalogue identity, source provenance, completeness and executable validity remain checked.

These removals allow reference designs and prompts to improve without rewriting tests that merely repeat their current values. No new fixtures or test cases were added for this cleanup. Existing focused regressions remain for actual bugs, including fractional projectiles, lost crosspath benefits, duplicate billing and dropped source passages.

## Runtime gates that need scrutiny

The default four-change ceiling counts representation fields, not distinct abilities. Four scalar improvements plus one bounded follow-up count as five changes. Slow and duration count twice; a whole manual boost counts once. This is not a defensible measure of player-facing complexity by itself. The separate early attack-identity and capability checks are closer to the user's requirement against overloading T1/T2.

The ceiling remains unchanged in this audit. It spans the blueprint schema, provider schema, decoder, validator, feasibility check and repair logic; removing one assertion would neither remove the limit consistently nor prove a better design. A future revision should separate a generous transport bound from gameplay capability limits and retain explicit caller budgets. Luffy's failed sample also lost promised behavior, so relaxing this ceiling alone would not make that candidate usable.

Typed plan promises also deserve scrutiny. The final free batch used ordinary damage and cadence dimensions for temporary boosts, and sometimes labeled retained properties as new improvements. Strict checking then correctly rejected the typed contract, even where its prose intended something else. That identifies a representation or translation failure. It does not establish that the underlying purchase idea was bad. Keep those diagnoses separate from impossible game mechanics and source-reading mistakes.

## Comparing workflows

At the time of this audit, the proposed next comparison used the existing direct and planned routes before adding another pipeline. PR6's compact single-call contract was a later candidate if direct authoring still exposed excessive bookkeeping. The revised compact experiment has since merged as opt-in. See [the PR decisions](PIPELINE-APPROACHES.md) for disposition and [next work](NEXT-EXPERIMENT.md) for the current roadmap.

Both dry-run plans were verified against the same retained Rimuru/Luffy/Goku corpus, model settings and rubric. Direct permits at most six authoring calls for three samples; planned permits twelve because each stage may repair once. No provider calls were dispatched in this audit, so these are call bounds, not observed speed or quality results. The existing `reference-patterns-v1` route can remain an offline-design comparator; a new workflow framework is unnecessary for these initial comparisons.

Apply the same frozen evaluator, source excerpts, requested game rules and review rubric to all returned candidates. Record ordinary mechanic legality separately from pipeline-specific plan-contract agreement. A plan object is not required for another route to receive a quality judgment. Failed generation still counts against delivery reliability, while retained partial proposals can receive qualitative comments without being published as valid Units.

Use a shared scorecard with separate results for source fidelity, understandable purchase differences, progression, crosspath inheritance, readability, completion rate, latency, tokens and cost. Each quality judgment needs the affected purchase and reason. An unreviewed dimension is unknown. Avoid a composite winner until those judgments have demonstrated agreement on accepted and rejected examples. PR8's scorer assigning every reference kit 100 is not that evidence.

The missing quality reference is a complete reviewed Unit, with explicit reasons its source adaptation and purchases work. It need not be a perfect design, nor the only acceptable answer. Establish that reference before adding more fixtures labeled as good output, expanding automated quality scoring or optimizing toward a numeric reward. The current reference recipes remain executable comparators, not accepted character designs. Do not freeze their exact prose or numbers as the definition of quality.

The cleanup verification passed all 394 then-existing tests, formatting and relative documentation links. This verifies the cleanup and retained software contracts; it does not change the previously recorded generation failures.
