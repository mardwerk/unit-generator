# Icon generation and model costs

UnitLab generates one selected icon through OpenRouter after explicit confirmation. It sends the icon prompt without regenerating the Unit. The default image model is `meta/muse-image`; `OPENROUTER_IMAGE_MODEL` can select another supported model. Each attempt makes one capability lookup followed by at most one generation request. There are no retries or automatic model/provider fallbacks.

Muse uses `GET /api/v1/models/meta/muse-image/endpoints` to confirm image output and a Meta endpoint, then `POST /api/v1/images` with `model`, `prompt`, `n: 1`, and `provider: { only: ["meta"], allow_fallbacks: false }`. The prompt requests a square image. Quality, dimensions, output encoding and background controls are omitted because Muse does not advertise them. The [Image API reference](https://openrouter.ai/docs/api/api-reference/images/generate-an-image) defines `n` as an upper bound from 1 to 10; providers restricted to single images reject values greater than 1. The adapter also rejects responses containing anything other than one image.

On September 21, 2026, the [general Muse endpoint record](https://openrouter.ai/api/v1/models/meta/muse-image/endpoints) returned HTTP 200 with image output, provider tag `meta` and recent traffic, while the [dedicated endpoint record](https://openrouter.ai/api/v1/images/models/meta/muse-image/endpoints) returned an empty endpoint list. General metadata therefore remains the Muse preflight source. Its presence does not establish successful generation or account routing eligibility.

One user-approved live test of the former chat adapter returned HTTP 404 with the exact provider instruction: "meta/muse-image is an image generation model and cannot be used with the chat/completions endpoint. Use the /api/v1/images endpoint instead." No image, usage or cost was returned. This established the wrong generation route as the cause of that request's failure. The adapter now uses the specified Image API directly, without trying the former chat route. A later test under the separately authorized evaluation budget used the corrected route and succeeded with one request, reporting $0.01, 348 input tokens and 2,418 output tokens. The returned 1600 by 1600 WebP was validated and normalized to PNG. Its opaque white background shows that transparency requested in the prompt is not guaranteed by Muse. The attack was the focal subject, but its busy outline was difficult to read at 48 pixels. This verifies routing and storage, not production icon quality. The receipt and image are retained under `.runs/logic-tuning/muse/2026-09-21T09-36-02.697Z/`. The local diagnostic retains the prompt, metadata, response and receipt under ignored `.runs/muse-diagnostic/2026-09-21T09-07-42.613Z/` without credentials.

Portrait prompts show the character's face, outfit and silhouette with no text. Basic attack prompts focus on the signature projectile, weapon, striking limb or impact, including only the body detail needed to explain it. Upgrade prompts focus on the changed mechanic and ask for an identity distinct from the basic attack and neighboring upgrades. Other ability prompts focus on their defining object or effect. The shared subject catalogue supplies both copied prompts and server generation. The image-only copy contains artwork instructions; the Codex copy adds the existing PNG destination and save instructions.

Other configured models retain the [dedicated Image API](https://openrouter.ai/docs/guides/overview/multimodal/image-generation), `POST /api/v1/images`. Capability discovery must advertise one image, low quality and square aspect ratio. The request pins that endpoint, requests PNG and requests transparent background only when advertised. This supports `openai/gpt-image-1-mini`; it is an explicit alternative, not a fallback. Its [provider pricing](https://developers.openai.com/api/docs/models/gpt-image-1-mini) lists $0.005 for a low-quality 1024×1024 image plus $2 per million input text tokens. An input of 200 text tokens would therefore give an estimated total of $0.0054.

[Muse's model page](https://openrouter.ai/meta/muse-image?output_modalities=image) publicly lists $0.01 per image. Its endpoint's raw $0.00000239520958083832 image-token rate is not a per-image price. Listed prices are estimates; the app retains provider-reported token usage and cost, including when image validation fails. Missing usage remains unknown. Public documentation and catalogue inspection do not establish availability, final billed cost or visual quality. The first diagnostic request failed before returning an image. The later budgeted test produced an inspected attack icon with the limitations described above; no comparison against another image model was run.

All configured image models use the dedicated API response format: canonical base64 raster bytes in `data[].b64_json` and an optional `media_type` of PNG, JPEG or WebP. Sharp verifies the decoded format against any declared MIME type, rejects animation and excessive pixel counts, and decodes the complete image into PNG for the existing local destinations. This preserves existing alpha and does not invent transparency or remove backgrounds. Remote image URLs, SVG and other formats are rejected without fetching them.

Limits are 1 MiB for capability metadata, 12 MiB for generation response JSON, 8 MiB for encoded-image bytes and the resulting PNG, and 16,777,216 decoded pixels. Image decoding has a 10 second processing timeout. The complete operation has a 120 second deadline and supports cancellation, including a stalled transport. HTTP redirects are rejected. Cancellation stops local waiting and aborts the request; it cannot guarantee the provider stopped generation or billing. Generated content is saved only after validation succeeds.
