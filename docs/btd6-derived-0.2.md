# Generalized tower-defense contract 0.2

The 0.2 adapter compiles three-path Units into a shared mechanical model. MangaMayhem imports the same mechanical operation schemas and runtime components for equivalent behavior. Version 0.1 remains available for historical replay; its stationary contact accounting is unchanged.

A Unit contains a base model, three paths with five upgrades each, costs and exact endpoint overrides. Captured families use `captured-endpoints` resolution and preserve all 64 legal endpoints. An unresolved captured endpoint has `model: null` and explicit `unsupported` reasons. Normal validation rejects unresolved models. Structural reference validation can allow them, and the compiler still refuses to execute a missing endpoint. This is a source-preservation format, not a qualification shortcut.

The compiler applies authored upgrades in path then tier order. Endpoint overrides replace the complete model only at that exact build; they never inherit into neighboring builds. Validation checks every resolved legal build and rejects purchases that change no combat state. Display range and cost do not establish purchase usefulness. `prepareBtd6CompilerV2` validates a private snapshot once for repeated build evaluation.

The shared scheduler orders expiry, round boundaries, activation, emission, impact and collection at the same timestamp. Event and target limits fail explicitly. Projectiles retain the emitted graph when later purchases or transformations change a unit. Aimed, straight and stationary projectiles use common collision code, with separate acquisition and collision detection, travel blockers, contact line of sight and child creation. Damage immunity consumes projectile contact capacity while skipping damage.

Actors have their own identities, attack clocks and lifetimes. Permanent actors can coexist with an activated subordinate while parent attacks are suppressed. Income produces a capped number of pickups per caller-supplied round; collection and expiry are explicit. Unique ally support changes actual attack range. Timed statuses share source identity, stacking policy and expiry with both game adapters. Event reactions and persistent zones use the same scheduler and target effects.

The runtime executes its declared policies. It does not prove that a static game capture fully specifies those policies. For example, Farm rate and emission count do not establish real-game round pacing, a Phoenix lifetime does not establish its flight path, and Paragon thresholds alone do not establish contribution ordering. Source mappings retain these distinctions.

Qualification requires structural validity, all requested models resolved, runnable behavior for every advertised mechanic, meaningful immediate purchase edges in applicable encounters, and explicit source mappings or declared adaptations. Default replacement also requires both adapter regressions, public schema loading, CLI/web output validation and reviewed arbitrary-subject examples. Passing a source field projection does not satisfy this gate.

Accounts use the shared ledger. A model declares qualified account profiles and can grant an account through a purchase or invoke an account operation through an ability. Account ability IDs are local to the owner. Scenario operations and `accountOperation` use qualified IDs such as `unit-id/bank-id`. All placements credit pickup collections to one wallet; account balances and loan debts remain separate. `end-round` is an explicit operation with an increasing round ID. Removing an account owner requires an explicit close operation, and retained debt stays in the ledger. A failed account ability does not consume its cooldown or activation allowance.

The encounter can update target positions and properties, replace a live target, or declare target descendants to create when a parent dies. These operations use the shared status lifecycle and refresh emitted projectiles. Child identities and distribution-blocking policy must come from the caller. No bloon layer hierarchy is inferred. Destruction effects requiring an external callback are rejected by this adapter until it has a corresponding host operation.

For layered enemies, the caller can instead supply `scenario.layers` with profiles, an explicit overflow allocation policy and a `createTarget` callback. Targets select a profile with `layer.profileId` and may declare a regrowth ceiling and clock policy. Both game adapters use the shared layer runtime. Overflow applies already resolved damage once, children remain live combat targets, and regrowth replaces an identity without awarding another pop. Explicit host removal cancels pending growth. Layer profiles and explicit replacement plans cannot be combined in one tower-defense encounter. Change a target's layer profile through replacement, not a property update. These supplied rules do not establish native BTD6 layer or regrowth parity.

Projectile `damageModifiers` evaluate live contact-target predicates against the frozen emitted owner through the common scalar modifier engine. The adapter applies the resulting damage and then target vulnerability once. This is the declared normalized modifier ordering; source array order alone does not prove native damage-order parity.

To refresh published schemas, build `@mardwerk/unit-definitions`, then run `node scripts/refresh-mechanics-schemas.mjs`. The script refreshes the public `tower-defense` Definition, standalone model schema, shared model schema and both MangaMayhem unit schemas from the executable TypeBox schemas. Run receipts record the Definition version, file digest and implementation version. Preserve those identifiers with outputs when comparing or revalidating earlier runs, since the 0.2 contract can gain optional operations. Historical `btd6-derived` 0.1 remains a separate Definition.
