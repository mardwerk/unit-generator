# Fixed reference patterns

The [implemented catalogue](../../src/core/mechanics/reference-patterns.ts) contains five complete version-2 proposed arrangements. It remains an optional `reference-patterns-v1` benchmark; that mode name identifies the selection contract, not the recipe version. The default v8 route is `planned-v1`, which designs the character repertoire and purchasing decisions before compiling numerical mechanics. A compatible punch or flame does not choose a complete recipe in that route. [Pipeline evaluation](../../docs/PIPELINE-EVALUATION.md) separates historical recipe results from current-route evidence.

The [English behavior filter](../../src/core/blueprint/attack-evidence.ts) excludes tested biographies, voice credits, bare skill names and flame-resistance/nullification inventories. Fire eligibility requires production, emission or burning behavior. It is a conservative retrieval heuristic, not semantic verification. The model sees bounded source context and origins to assess actor identity, negation and source-period restrictions. It does not retype quotes or classify modalities. The [adapter](../../src/core/blueprint/reference-authoring.ts) copies the exact full selected span and falls back to the character name when a motif is not grounded. Within reference mode, custom tasks, edited rules, explicit constraints and revision history fall back to direct authoring; fixed patterns apply only to the unchanged starter request contract. The default planned route handles those edits and revisions through planning.

These recipes retain focused early improvements, a supported T3 transition and strong T5 development. Those are catalogue choices rather than universal authoring gates. Manual boosts occur only on path2; the area recipe is entirely automatic. Crosspaths retain early modifiers without acquiring another advanced path. Explicit distinct-target volleys and bounded follow-ups use the v8 extensions; ordinary repeated projectiles still share a primary target. Beam delivery is periodic, not a continuous sweep. Damage immunities, detection and control exclusions remain explicit in each blueprint. See [mechanics documentation](../../docs/MECHANICS.md).

The progression draws on the [26-tower source package](raw/btd6_towers.json) and [pattern analysis](PATTERNS.md), including Dart's early stat choices, Wizard's attack development, Glue's sustained pressure and Boomerang's timed self boost. It does not transcribe those towers. Source JSON SHA-256 is `a2a5e2bb4591a6278f079a6796d06f76428716080bd4a42453f898cb1403f8f6`; [provenance](provenance.json) records the retained files. The package combines unpinned snapshots and lacks normalized per-upgrade combat stats.

All prices are authored incremental Gold proposals. Catalogue purchases range from 120 to 300 at T1, 850 to 2000 at T3, 3200 to 7500 at T4, and 24000 to 42000 at T5. Their T5/T4 price ratios range from about 4.33 to 7.5. These fit within the broad corresponding ranges of the named Dart, Boomerang, Glue and Wizard records. Similar price scale does not establish similar power, affordability or balance. Every recipe records this limitation and an explanation for each purchase.

The recipes retain large specialty gains as proposed examples. The default authoring policy no longer requires a universal 3x gain, different broad role labels or a new T3 operator. Custom Definitions can request those gates. Direct, group and control capacity remain analytical estimates; peak active output is not time-averaged combat output. These recipes do not establish useful activation timing, target access or gameplay balance.

Run the offline catalogue verification from the unit-generator directory:

```sh
pnpm exec tsc -p tsconfig.test.json
node --test .test-build/tests/reference-patterns.test.js
```

The [tests](../../tests/reference-patterns.test.ts) validate each complete blueprint under the current authoring Definition, resolve all 64 legal selections per recipe and check their boosted attacks, for 320 builds total. They also check compatibility, immutable catalogue data, invalid fractional counts and the nonburn recipe's status-free inheritance. Compatibility compares rules, progression, currency and reference scale; per-recipe validation still handles customized policy and ceilings. Separate [candidate tests](../../tests/attack-evidence.test.ts), [routing tests](../../tests/reference-routing.test.ts) and [adapter tests](../../tests/reference-authoring.test.ts) cover source filtering, custom-request preservation and selection. They do not certify the meaning of quoted passages.

These checks establish executable consistency, not balanced waves, maps, prices, character fidelity or player preference. Sustained 90% slowing needs playtesting. Similar scalar progressions will recur across characters, and the catalogue lacks support, economy, independent actors and many source-specific effects. A character can use a faithful supported subset while reserving other abilities; an unsuitable source should receive an honest refusal. Do not rename a fixed operator to imply a power it does not implement.
