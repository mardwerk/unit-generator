# Fixed evaluation protocol

This is the initial protocol planning record. The completed study expanded the run matrix and obtained Luna execution authorization, as recorded in the root study files and comparison report. Protocol 1.0.0 was frozen before new pipeline results. The prior Luffy review informed these evaluation questions. The known saved Luffy artifacts are development examples, never holdout evidence. This directory is evaluator-only and contains the withheld user preference. Do not pass this rubric, review notes or preferred target to name-only generators.

Use baseline plus three new pipelines, two repeats each if authorized. Hold the model, captured source bytes, input, default definition, call ceiling, output-token ceiling and repair allowance constant. Register exact values and hashes before starting. Compare separate name-only and designer-brief tracks; a brief cannot be silently added to the name-only track. No paid calls are authorized for this prototype. A later runner must obtain authorization before those calls.

The common evaluator is `evaluateCandidate(unit, { research, input })` exported by `evaluate.mjs`. `unit` is a raw UnitSpec, or null for a failed attempt. `research` is the unmodified research payload. `input` is the actual generation request. The evaluator never edits candidates and never consumes a pipeline's self-rating. Runner outcomes and accounting remain separate from UnitSpec. A refusal or transport failure has no unit; retain the full outcome and do not mislabel it schema-invalid.

The evaluator calls real hard and classic-profile validators, compiles representative selections and simulates the six fixed built-in scenarios. It returns issues, build/report evidence, diagnostic findings and explicitly unassessed review dimensions. It also executes a fixed distant-target probe at 50 world units with ability use disabled, reporting actions and damage without deciding whether the result is faithful melee. The 50-unit probe is a source-neutral diagnostic of reach, not a pass threshold for quality. Radius, collision, dodge, runtime transformations and player enjoyment are outside this simulator.

Human or independent Astra review uses `rubric.json`. Reviewers inspect source excerpts, research, unit pointers, operation audits and simulations. They record supported, partial, contradicted, unassessed or not-expressible per question with concrete evidence. No names-only or keyword tests establish adaptation. The current default cannot implement all preferred Gear forms as runtime transformations. Record that feasibility gap separately from what the candidate represents and whether its limitations are honestly described.

Freeze before evaluation:

1. Save run manifest with model, source and definition hashes, call ceiling, token ceiling, repair count, eight assigned run slots and raw artifact locations.
2. Assign opaque labels Q17, Q42, Q63, Q88 for repeat one and Q26, Q51, Q74, Q95 for repeat two by a concealed permutation of pipeline identities. Keep the mapping outside review packets. Label assignment must precede outcomes. All six pairs within each repeat are reviewed; reverse left/right order for the second reviewer.
3. Give reviewers the same source evidence and rubric, with pipeline names, prompts, self-assessments and cost hidden. Preserve character names and mechanics because source fidelity requires them. Reveal accounting only after content judgments.
4. Record left, right, tie, incomparable or insufficient-evidence for each dimension and each pair. Require citations or unit pointers and distinguish supported judgments from unresolved interpretation. Retain disagreement. A model reviewer is fallible and cannot certify its own judgment.
5. Reveal identities after review. Present validity, source fidelity, organization, behavior, upgrade usefulness, prose correspondence, feasibility, traceability and accounting separately. Show all attempts; never pick one winner per pipeline and erase failures. Eight runs provide descriptive evidence, not reliable statistical ranking.

There is no overall quality score. Existing diagnostic heuristics remain uncalibrated mechanical observations. A transport failure differs from an invalid unit, an honest infeasibility report differs from either, and none receives an invented fidelity score. Source research coverage and source organization are reviewed independently of implementation validity.

The [original freeze record](../evidence/evaluation-freeze.json) records SHA-256 for the original local protocol and rubric. This checked-in copy is formatted; the root experiment README describes the serialization differences. `evaluate.mjs` includes those hashes in each report; after implementation, its hash is recorded too. Any change after new-result inspection requires a new protocol version and disclosure, not quiet tuning. The only initial smoke test uses saved development artifacts and a synthetic invalid object.
