# Feasibility, full draft and atomic review

This prototype combines a compact public feasibility plan with the existing full-DSL patch workflow. It keeps every capability of the bundled classic output schema. It does not lower a restricted intermediate language, change validation, or hardcode a character or preferred path arrangement.

`createPrototype({ artifactDir })` returns the normal resolved Definition. Pass it to real core `generate` with successful shared research and the coordinator's Luna adapter. The builder makes no provider calls. The coordinator owns model choice, reasoning, streaming and spending limits.

The normal sequence uses three calls:

1. Feasibility and source allocation. The model receives numbered facts, the actual request, classic rules and effective limits. It records supported, adapted and unsupported requests, a base attack, three paths with five progression changes each, the declared mechanic inventory, omissions and uncertainties.
2. Full DSL draft. The existing patch workflow receives the public plan and writes the unchanged complete UnitSpec.
3. Source review and atomic edits. It receives real validation, sampled simulation diagnostics and the prospective execution inspector. Only a complete transaction passing unchanged schema, system and request checks can replace the draft.

One outer atomic repair is available for an invalid result, for a maximum of four model calls. A rejected or failed review preserves the draft. Preserving an invalid draft still produces a failed core result. There is no hidden model scorer or automatic full-document rewrite.

The plan deliberately has no duplicated alternative IDs or DSL identifiers to reconcile. Its source indices and shape are checked. A malformed plan or nonexistent citation stops before drafting. A planned range or prominent-mechanic excess becomes an explicit planning issue for the draft, retaining the original discrepancy. This plan is a model judgment, not a trusted feasibility proof. The actual output must still pass the unchanged validators.

Effective limits read the loaded definition's `maxRange`, `maxManualAbilities` and `maxProminentMechanics` configuration. Request keys are `noManualAbilities`, `maxProminentMechanics` and `placementCostBand`. Default medium cost is 450–750 credits. Every declared ability and form counts toward prominent mechanics, including locked declarations. Control and damage over time each add one category. Runtime transformation and mutually exclusive modes remain unavailable. An encounter form or attack upgrade must not be described as implementing those behaviors.

The planner records meaningful omitted source distinctions when they cannot fit. A supported subset can therefore validate without satisfying every requested design preference. The returned `design.feasibility` preserves that difference for review. Source indices assert support; they do not establish that the final operations implement the cited meaning. Independent content review remains necessary.

The execution inspector adds the actual scheduled period, `max(trigger.intervalSeconds, timing.cooldownSeconds)`, and compiled form action inventories. Its findings concern recurring scheduled attempts, not every invocation route or the complete value of an upgrade. It makes no inference that primary target count caps collateral projectile pierce. The six built-in simulation scenarios and representative builds remain samples. Nothing here produces an aggregate quality number or proves balance.

Files prefixed `00-feasibility` retain the initial call, raw response and checked plan with effective limits. `execution-review-patch`, `execution-repair` and `execution-final-*` retain deterministic inspector results. The reused patch workflow writes its draft, validation, proposals and transaction outcomes. Its own saved call templates omit this wrapper's appended plan and execution fields; the coordinator's `call-N-input.json` files retain the actual final model requests. All requests exclude raw source bodies and the complete ResearchResult.

Run the offline checks from the repository root:

```sh
node --test experiments/luffy-pipelines/combined/offline.test.mjs
```

Six real-core checks cover preserved forms and full schema, numbered facts, exact effective configuration, a fourth-call repair, valid-draft preservation, exhausted repair and invalid source references. They test orchestration and real validation. They are not evidence of generated design quality.
