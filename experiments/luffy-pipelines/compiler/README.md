# Compact design compiler prototype

This experiment asks whether a smaller typed language helps Luna produce a valid, source-specific design with fewer output tokens and fewer repairs. The compiler expands explicit mechanical choices into the unchanged classic UnitSpec. It does not choose a character's attacks, path themes, prices, ranges, timing, or upgrade values.

`prototype.mjs` exports `async createPrototype({ artifactDir } = {})`, which returns the normal resolved Definition. Run it through the real core `generate` function with supplied `input.knowledge` and a Luna model adapter. It also exports `irSchema`, `lowerIR(ir, knowledge)`, and `representability` for offline inspection. The Definition retains the bundled input/output schemas, preflight, configuration and trusted validation functions. No provider, model setting, environment variable, network client or character-specific data is embedded here.

The exact maximum is three creative model calls: one IR draft, followed by up to two targeted IR repairs. Each repair gets the previous IR and actual compiler or trusted-validator issues. It returns a complete replacement IR. The workflow stops as soon as validation passes. Research runs once with the supplied research bundle and is reused by core. There are no role calls, model-based scorer calls, hidden drafting calls or downstream core repair calls. Set the caller's `maxModelCalls` to at least three to permit the full budget. Core's `metadata.modelCalls` counts all three; `metadata.repairs` counts outer-core repair iterations only and is zero because this workflow owns its repair loop. Call stages identify its repairs.

Array indices identify actions and evidence claims. The compiler creates syntax IDs and same-path prerequisites. Changes are absolute values, so the model does not need to calculate products across cumulative tiers. Each property belongs to one path, and the real validator checks every legal selection. A disabled manual action's enable change produces both `enable-action` and `grant-ability`. Manual cooldown upgrades are rejected because this IR does not expose matching ability-timing changes.

Supported effects are direct damage, single-stack damage over time, a single-stack status per action, forced movement with one application per target, and reveal. Each action independently chooses delivery, targeting, range, cadence, windup, shots and pierce. Projectile speeds, area radii and zone lifetimes are explicit when their delivery needs them. At most one manual action is available. Resources, forms, states, summons, secondary actions, economy income, tag filters, stacking, action replacement, custom placement and asset requirements are outside this IR. This is a subset experiment, not full DSL parity. The prompt asks the model to list meaningful omissions and forbids claiming omitted mechanics in prose.

Game defaults are recorded in the exported `representability.defaults` and saved with every source map. They are land placement with radius 1, durability 100, empty tags and asset requirements, one aggregate emitter, an interval scheduling floor of 0.15 seconds, refresh/expiry for one-stack statuses and damage over time, and a one-charge manual ability with no initial delay and recharge equal to its selected cooldown. The model selects actual placement cost within medium 450–750 unless the request explicitly sets low 200–400 or high 800–1200. All action and base ranges are model choices. Structural IDs and fixed defaults carry no character meaning.

Artifacts for attempt N are `N-call.json`, `N-ir.json`, `N-lowered-candidate.json`, `N-source-map.json`, and `N-issues.json` when that attempt fails. An IR failure has no lowered candidate. If repairs exhaust after any attempt lowered successfully, the workflow returns the last lowered candidate and its design issues so normal outer validation retains a failed candidate. If no attempt lowers, it returns an explicit workflow failure. Source maps connect zero-based knowledge claim indices and their source IDs to action pointers and exact upgrade operation pointers. Omissions and limits accompany the map. The successful core result also exposes these in `design`. Mappings record asserted support; they do not prove that a claim entails the operation or that the summary is accurate.

Review strategy: apply the same independent evaluator to the final UnitSpec as to the other prototypes. Review source-to-operation mappings against the supplied claims, then compare paths by their actual operations and legal builds. Inspect omissions separately. Do not count claimed features, invented names or raw evidence citations as implemented coverage. Measure calls, tokens, latency, hard acceptance and repair use separately from source fidelity. No evaluator or hidden target was read to construct this variant.

Offline checks use the real core runner and trusted classic validators. They cover valid compilation, distinct delivery/range/emissions, malformed IR, missing claim/action references, independent property ownership, manual unlocks, bounded model repair and a real range-contract failure. Run:

```sh
node --test experiments/luffy-pipelines/compiler/offline.test.mjs
```

Six tests pass. There have been no live model calls from this builder. Live Luna measurements belong to the parent coordinator.

ponytail: the narrow IR cannot express every classic mechanic. Revisit the supported language only if live evaluation shows a specific needed mechanic is being omitted or falsely approximated. Do not silently expand it with character-specific compiler behavior.
